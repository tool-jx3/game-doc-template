## Why

Full rulebook translations run to hundreds of pages, and today every draft is generated by a Claude session (main-thread `sonnet`, or an `opus` subagent inside `super-translate`). Draft generation — not review — is the highest-token step in the pipeline, and it doesn't need Claude's judgment: it needs a first-pass translation that a subsequent review gate can catch problems in. When a local Codex CLI is available and authenticated, routing draft generation to a cheaper GPT model at low reasoning effort keeps Claude's token spend concentrated on the parts of the pipeline that actually need it — review, terminology decisions, structural validation — instead of on bulk prose generation.

- Because this project is a template copied by other users (via `/new-project`), the whole feature is gated behind a persisted, per-project preference in `style-decisions.json` — asked once on the first run of any of the three skills, never re-asked. Users who don't want their translation work routed to Codex at all (regardless of whether it's installed) can decline once and never see it again.
- When tiering is enabled, `translate`, `super-translate`, and `bilingual-translate` gain a Codex-backed draft path: when Codex is available and authenticated, the draft-generation step is delegated to Codex (low-tier model, low reasoning effort) instead of being written directly by the Claude session/subagent. This is unconditional whenever Codex is usable — no per-run opt-out.
- The existing draft-first / self-review-before-writeback contract in all three skills is unchanged and becomes the verification gate for Codex-authored drafts — Claude still reviews and can reject or revise before writeback. No skill overwrites source or bypasses review because the draft came from Codex.
- If tiering is enabled but Codex isn't installed, and `npm` is available, the skill offers a one-time install prompt (mirroring `codex:setup`'s flow). If the user declines, the decision is recorded in auto memory so future runs do not re-ask about installing (tiering itself stays enabled; installation just isn't offered again).
- If Codex is unavailable (not installed and declined, or installed but erroring/failing mid-run), the skill falls back to the current Claude-only draft path with no user-visible disruption.
- **BREAKING**: none — this is additive routing behind an opt-in preference and an availability check; the Claude-only path remains the default whenever tiering is disabled or Codex isn't usable.
