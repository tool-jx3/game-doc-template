## Purpose

Lets `translate`, `super-translate`, and `bilingual-translate` delegate bulk draft-generation token spend to a cheaper local Codex model when one is available and the project has opted in, while keeping Claude as the unconditional review gate before any writeback.

## ADDED Requirements

### Requirement: Project-level Codex tiering preference
This project template is copied by other users via `/new-project`. Before any Codex routing or availability probing happens, each project SHALL have a persisted, per-project preference (`style-decisions.json`) for whether Codex-based draft tiering is used at all. The preference is asked once, on the first run of `translate`, `super-translate`, or `bilingual-translate` in a project where it is unset, and is never re-asked afterward.

#### Scenario: First run, preference unset
- **WHEN** `translate`, `super-translate`, or `bilingual-translate` runs and `style-decisions.json` has no Codex tiering preference recorded
- **THEN** the skill asks the user once whether to enable Codex-based draft tiering for this project, and persists the answer before proceeding

#### Scenario: Preference already recorded
- **WHEN** any of the three skills runs and a Codex tiering preference is already recorded in `style-decisions.json`
- **THEN** the skill uses the recorded preference directly and does not ask again

#### Scenario: Preference disabled
- **WHEN** the recorded preference is disabled
- **THEN** the skill never probes for Codex availability, never offers to install Codex, and always generates drafts in the Claude session/subagent, for every run in this project

### Requirement: Codex availability detection
When the project's Codex tiering preference is enabled, the skill SHALL detect whether a local Codex CLI is installed and authenticated before generating each draft.

#### Scenario: Codex installed and authenticated
- **WHEN** tiering is enabled and the skill reaches the draft-generation step with Codex installed and authenticated
- **THEN** draft generation routes to Codex instead of being written directly by the Claude session/subagent

#### Scenario: Codex not installed, npm available, no prior decline on record
- **WHEN** tiering is enabled, Codex is not installed, `npm` is available, and no prior "declined Codex install" memory entry exists for this project
- **THEN** the skill asks the user exactly once whether to install Codex before falling back to the Claude-only draft path for the current run

#### Scenario: Codex not installed, prior decline on record
- **WHEN** tiering is enabled, Codex is not installed, and a prior "declined Codex install" memory entry exists for this project
- **THEN** the skill does not ask again and proceeds directly on the Claude-only draft path

### Requirement: Default Codex model and effort for draft generation
When routing draft generation to Codex, the skill SHALL use a low-cost, low-reasoning-effort model by default, matching the project's mechanical-task routing convention, unless the user has explicitly requested a different model or effort for the run.

#### Scenario: Default routing
- **WHEN** the skill routes draft generation to Codex with no explicit model/effort override
- **THEN** it invokes Codex with the project's default low-tier model and low reasoning effort

#### Scenario: Explicit override
- **WHEN** the user explicitly requests a different Codex model or effort level for the run
- **THEN** the skill uses the requested model/effort instead of the default

### Requirement: Claude review gate is unconditional
Regardless of whether a draft was generated by Codex or by the Claude session/subagent, the draft MUST pass the skill's existing self-review (or reviewer subagent, in `super-translate`) checklist before writeback. The origin of the draft SHALL NOT change the review criteria or allow the review step to be skipped.

#### Scenario: Codex-authored draft fails review
- **WHEN** a Codex-authored draft fails the skill's self-review or reviewer checklist
- **THEN** the skill handles it exactly as it would a failing Claude-authored draft (fix directly in `translate`/`bilingual-translate`; refiner loop in `super-translate`) — it is never written back unreviewed

#### Scenario: Codex-authored draft passes review
- **WHEN** a Codex-authored draft passes the skill's self-review or reviewer checklist
- **THEN** writeback and progress-tracking proceed exactly as for a Claude-authored draft, with no behavior difference visible downstream

### Requirement: Fallback on Codex failure
If a Codex invocation fails, errors, or times out during draft generation, the skill SHALL fall back to generating that file's draft directly in the Claude session/subagent, without aborting the overall translation run.

#### Scenario: Codex invocation fails mid-batch
- **WHEN** a Codex draft-generation call fails for one target file during a batch run
- **THEN** the skill generates that file's draft directly instead and continues the batch; other files in the batch are unaffected

### Requirement: Install decline is remembered
If the user declines the one-time Codex install offer, the skill SHALL record that decision in persistent memory so future runs in this project do not re-prompt about installing — independent of, and without changing, the project's overall tiering preference.

#### Scenario: User declines install
- **WHEN** the user declines the Codex install offer
- **THEN** the skill writes a memory entry recording the decline for this project, and no later run of `translate`, `super-translate`, or `bilingual-translate` in this project asks about installing again, even though tiering remains enabled and availability is still checked silently on each run
